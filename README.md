# ПР10 — Облік прокату спортивного інвентарю (варіант 12)

**Навчальний прототип на C# / .NET 8.** Це продовження практичних робіт №3–9.
Застосунок має консольне меню, модель предметної області, окремі сервіси й JSON-сховища.

## Вимоги
- Windows 10/11, Linux або macOS з **.NET SDK 8.0**.
- Visual Studio 2022 з навантаженням **.NET desktop development** (або команда `dotnet`).
- Пакети NuGet з Інтернету не потрібні.

## Запуск
1. Розпакуйте ZIP у звичайну папку, не запускайте проєкт з архіву.
2. Відкрийте `SportsRental.sln` у Visual Studio.
3. Оберіть стартовий проєкт `SportsRental.Console`.
4. Натисніть **Build → Build Solution**, потім **Ctrl+F5**.
5. Або з кореня репозиторію виконайте:

```powershell
dotnet build SportsRental.sln
dotnet run --project SportsRental.Console -- --data ./data
```

Після першого запуску створяться `data/clients.json`, `data/inventory.json`, `data/rentals.json`, `data/tariffs.json`.
Чотири файли відповідають накопичувачам D2, D1, D3 і D4 з DFD ПР6.
`--data ./data` задає папку даних; без параметра використовується папка `data` відносно поточного робочого каталогу.

## Перевірка

```powershell
dotnet run --project SportsRental.Console -- --self-test
```

Очікувано запускаються **40 автоматизованих тестів** у власній тимчасовій папці, не зачіпаючи робочі JSON.
**Фактичний результат потрібно перевірити на комп'ютері з .NET SDK:** у середовищі підготовки файлів компілятор .NET був недоступний.
Також виконайте вручну: реєстрація → інвентар → оформлення → звіт → вихід → повторний запуск → перевірка збереження → повернення.

## Основні пункти меню
1. Інвентар: створити, знайти, перелік, перейменувати, видалити, ремонт.
2. Клієнти: створити, знайти, перелік, редагувати, видалити.
3. Оформити прокат. Програма відмовляє у видачі зайнятого/несправного інвентарю.
4. Повернути інвентар. За потреби відправити на обслуговування.
5. Звіти з фільтром за статусом і підсумковою сумою.
6. Тарифи, зокрема зміна погодинної ставки.
7. Демонстрація наслідування й поліморфізму з ПР9.
8. Табуляція вартості з ПР7.
9. Масиви, матриця і рекурсія з ПР8.
0. Вихід.

## Тарифи (навчальні припущення)
| Категорія | Грн/год | Вихідний | Більше 72 год |
|---|---:|---:|---:|
| Велосипед | 40 | ×1.20 | ×0.90 |
| Лижі | 55 | ×1.25 | ×0.85 |
| Намет | 35 | ×1.10 | ×0.80 |

Усі чотири варіанти комбінацій умов реалізовано у `RentalItem.CalculateByDecisionTable()` через `switch` за кортежем.
Фактична дата початку задає ознаку вихідного; при поєднанні умов коефіцієнти перемножуються.
Тривалість: 1–336 годин. Після оформлення сума фіксується й не змінюється при зміні тарифу.
У ПР6 тариф був описаний як денний; для ПР7–10, відповідно до формулювання ПР7, використано погодинну ставку.

## Шарова структура
- `SportsRental.Core/Models`: `Client`, `InventoryItem`, `Rental`, `Tariff`, `RentalItem` → `Bike`, `Skis`, `Tent`, статуси.
- `SportsRental.Core/Repositories`: `IRepository<T>`, `JsonRepository<T>`.
- `SportsRental.Core/Services`: `ClientService` (DFD2), `InventoryService` (DFD1), `RentalService` (DFD3/4), `ReportService` (DFD5), `TariffService` (D4).
- `SportsRental.Core/Analytics`: приклади одновимірних/двовимірних масивів і рекурсії з ПР8.
- `SportsRental.Console`: меню, перевірка введення, `--self-test`.
- `docs`: звіт, схема класів та інструкція.
- `data`: **лише навчальні приклади**. Робочі JSON ігноруються Git, бо можуть містити дані людей.

## Обмеження / відкладені функції
Немає онлайн-бронювання, SMS, онлайн-оплати, інтеграції з бухгалтерією, GPS та роботи декількох філій.
Кожен JSON-файл перезаписується через тимчасовий файл; спільна транзакція між декількома JSON не реалізована.
Використовувати прототип лише для навчальних даних. Для реальної роботи потрібні авторизація,
резервне копіювання, блокування одночасних записів, транзакційна база та захист персональних даних.

## Доповнення для курсового проєкту: CRUD прокатів (D3)

Пункт **10 головного меню** відкриває керування прокатами: створити, знайти, переглянути,
виправити активний запис і скасувати помилково відкритий активний запис.
Виправлення перераховує вартість за тарифом. Скасування повертає предмет у стан `Available`.
Завершені прокати не редагуються й не видаляються, щоб зберегти історію.
Нові автоматизовані перевірки **T41–T48** покривають ці правила; очікувано загалом 48 тестів.
Перевірка на Windows: `dotnet run --project SportsRental.Console -- --self-test`.

**Примітка:** якщо ви використовуєте Git-репозиторій, спочатку протестуйте цю версію на своїй машині,
а тоді перенесіть зміни до основної гілки. Файли `data/clients.json`, `data/inventory.json`,
`data/rentals.json`, `data/tariffs.json` не слід додавати до публічного репозиторію.
